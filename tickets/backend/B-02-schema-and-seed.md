# B-02: Схема данных и сид-данные

**What to build:** После запуска в системе уже есть компания из датасета: подразделения, сотрудники всех четырёх ролей, категории с ответственными и заместителями, сроки по приоритетам и двадцать обращений A-001…A-020 с датами. Среди них есть просроченные, и по ним считается время первого ответа.

**Blocked by:** B-01 «Контракт API и мок-сервер»; B-17 «Каркас бэкенда, тестовая обвязка, адаптеры и фоновые задачи»

**GitHub:** [#3](https://github.com/Blckk699/modus-trade-feedback/issues/3) — статус и обсуждение ведутся там

**Истории из SPEC.md:** —

- [ ] Схема содержит все сущности из раздела «Схема данных» спеки
- [ ] Сид создаёт восемь подразделений из спеки с руководителями, собственника и администратора
- [ ] Все двадцать обращений датасета загружены с исходными типом, категорией, приоритетом, статусом и текстом
- [ ] Даты обращений отсчитываются от момента загрузки: в любой день минимум три обращения просрочены и минимум пять имеют время первого ответа
- [ ] Роли сида закрепляются за реальными Telegram-аккаунтами команды через файл настроек вне репозитория; если аккаунт для роли не задан, сид сообщает, под какой ролью никто не сможет войти
- [ ] Команда сброса возвращает демо-данные в исходное состояние; повторный запуск не создаёт дублей
