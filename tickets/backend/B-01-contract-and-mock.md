# B-01: Каркас, контракт API и мок-сервер

**What to build:** Остальные три пачки получают зафиксированный контракт API и мок-сервер и начинают работу, не дожидаясь готового бэкенда. Контракт покрывает все операции, нужные 70 историям спеки: вход, обращения, переписка, статусы, маршрутизация, повторы, обсуждения, лента, совещания, сводка, настройки, Битрикс24, уведомления для бота.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Истории из SPEC.md:** все

- [ ] Проект бэкенда запускается одной командой вместе с базой данных
- [ ] Контракт в формате OpenAPI описывает все сущности из раздела «Схема данных» и операции для каждой строки матрицы доступа
- [ ] В контракте описаны ошибки доступа и ошибки недопустимого перехода статуса
- [ ] Мок-сервер поднимается из контракта одной командой и отдаёт правдоподобные ответы на примерах из датасета
- [ ] Контракт и инструкция по запуску мока переданы пачкам фронта, Flutter и Telegram
- [ ] Заведён тестовый каркас на уровне HTTP API с управляемым временем и одним образцовым тестом; следующие тикеты пишут тесты по этому образцу
- [ ] Внешние сервисы (Claude, ElevenLabs, Telegram, Битрикс24) объявлены как адаптеры с подменой в тестах, даже если реализации ещё нет
- [ ] Зафиксировано правило: контракт меняет только владелец этой пачки и сообщает об изменении остальным
