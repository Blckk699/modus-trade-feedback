# B-01: Контракт API и мок-сервер

**What to build:** Три клиентские пачки получают зафиксированный контракт API и мок-сервер и начинают работу, не дожидаясь готового бэкенда. Контракт покрывает все операции, нужные 70 историям спеки, включая dev-вход и действия бота от имени пользователя.

**Blocked by:** None (can start immediately)

**GitHub:** [#1](https://github.com/Blckk699/modus-trade-feedback/issues/1) — статус и обсуждение ведутся там

**Истории из SPEC.md:** все

- [ ] Контракт в формате OpenAPI описывает все сущности из раздела «Схема данных» и операции для каждой строки матрицы доступа
- [ ] В контракте описаны вход через Mini App, Telegram Login, код из бота, dev-вход и сервисная авторизация бота
- [ ] В контракте описаны ошибки доступа и ошибки недопустимого перехода статуса
- [ ] Мок-сервер поднимается из контракта одной командой и отдаёт правдоподобные ответы на примерах из датасета
- [ ] В инструкции к моку прямо сказано, что он не хранит состояние
- [ ] Контракт и инструкция по запуску мока переданы пачкам фронта, Flutter и Telegram
- [ ] Зафиксировано правило: контракт меняет только пачка бэкенда и сообщает об изменении остальным
