## Общие правила для всех пачек

- Источник истины — `SPEC.md` в корне рабочей папки. Тикет не повторяет спеку, а ссылается на номера историй.
- Контракт API ведёт пачка бэкенда (тикет B-01). Клиенты не меняют контракт сами: расхождение передаётся владельцу бэкенда.
- До готовности бэкенда клиенты работают на мок-сервере из контракта. Мок не хранит состояние: клиентский тикет на моке закрывается, когда экраны готовы и отправляют запросы по контракту. Поведение подтверждается на реальном сервере в тикетах ранней и полной интеграции (W-10, F-10, T-08, W-09, F-09, T-07).
- Локально и на моке вход выполняется через dev-вход. На сервере для демо он выключен.
- Вся бизнес-логика живёт в бэкенде. Клиент не дублирует правила прав, сроков и маршрутизации, а скрывает недоступные действия по данным API.
- В продукте не должно быть заглушек: функция либо работает целиком, либо её нет в интерфейсе.
- Интерфейс только на русском. Данные только синтетические.
- Срок сдачи: пятница, 13 ноября, 14:00. Заморозка изменений: четверг вечером.

## Репозиторий и статусы тикетов

- Монорепозиторий, у каждой пачки своя папка: `contract/` и `backend/` — бэкенд, `web/` — фронт, `flutter/` — Flutter, `bot/` — Telegram. Пачка пишет только в свою папку. `contract/` меняет только бэкенд. Исключение: T-06 правит модуль входа в `web/`.
- Каждая пачка работает в своей ветке: `pack/backend`, `pack/web`, `pack/flutter`, `pack/telegram`. После закрытия тикета ветка вливается в `main` через pull request, когда тесты зелёные.
- Перед взятием тикета пачка подтягивает `main`, чтобы получить свежий контракт.
- Тикеты ведутся в GitHub Issues репозитория, блокировки проставлены там нативно. Файлы в `tickets/` — копия для чтения, статус в них не меняется.
- Взял тикет — назначь себя исполнителем и замени метку `ready-for-agent` на `in-progress`. Pull request закрывает задачу строкой `Closes #N`; отметь в задаче выполненные критерии.
- Тикет можно брать, только когда закрыты все задачи из его «Blocked by».
- Метки пачек: `pack:backend`, `pack:web`, `pack:flutter`, `pack:telegram`. Свободные тикеты пачки: фильтр по метке пачки и `ready-for-agent`.
- Секреты в репозиторий не попадают: ключи сервисов, токен бота, Telegram ID команды.
