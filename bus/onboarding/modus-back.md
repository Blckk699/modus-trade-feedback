# n1kollo: пачка бэкенда

Ваш агент на шине — `modus-back`. Он делает тикеты бэкенда: контракт API, мок-сервер, сам бэкенд и тесты.

## Что у вас будет

- Приглашение в репозиторий `Blckk699/modus-trade-feedback` — придёт письмом от GitHub, примите его.
- Файл `modus-back.token` — Александр передаст лично. Это пароль агента: никому не пересылайте и не показывайте агенту.

## Подключение (10 минут)

Пошагово — в `bus/README.md`. Коротко:

```bash
git clone https://github.com/Blckk699/modus-trade-feedback.git
cd modus-trade-feedback
sh bus/setup-bus.sh ~/.config/modus-bus/modus-back.token
```

На Windows вместо последней строки:

```powershell
powershell -ExecutionPolicy Bypass -File bus\setup-bus.ps1 $env:USERPROFILE\.config\modus-bus\modus-back.token
```

Откройте Claude Code в папке репозитория и проверьте `/mcp`: сервер `bus` должен быть подключён.

## Стартовое сообщение агенту

Скопируйте целиком:

> Ты агент `modus-back`, пачка бэкенда. Прочитай `CLAUDE.md`, `SPEC.md` и `tickets/README.md`. Отметься на шине: `bus_status(state="idle", model=<твой полный id модели>, machine=<имя машины>)`, затем проверь почту `bus_inbox`. Свои тикеты бери по `gh issue list --label agent:modus-back --label ready-for-agent`, начиная с тех, у которых закрыты все блокеры. Первыми идут B-01 (контракт API и мок-сервер) и B-17 (каркас, тесты, адаптеры): от B-01 ждут все три клиентские пачки, поэтому отдай контракт и мок как можно раньше и разошли их агентам `modus-front` и `modus-flutter` через шину. Работай по правилам из `CLAUDE.md`: одна ветка и один PR на тикет, `pr_ready` ревьюеру, свой PR не мержишь, на сервер не ходишь.

## Что важно именно для бэкенда

- Вы владелец контракта API: только ваша пачка меняет `contract/`. Остальные присылают вопросы через шину.
- Развёртывание (B-16) делает Александр. Ваша задача — чтобы бэкенд запускался одной командой и в `main` была инструкция по запуску.
- B-01 и B-17 можно вести двумя агентами параллельно; второй агент (субагент) работает под тем же токеном.
