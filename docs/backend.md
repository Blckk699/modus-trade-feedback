# Бэкенд: описание для проверки

Система обращений и предложений сотрудников. Бэкенд хранит всю бизнес-логику: права, маршрутизацию, сроки, склейку повторов и эскалацию. Клиенты (Telegram-бот, Mini App, Flutter, веб) работают через один HTTP API.

Контракт API: `contract/openapi.yaml`. Требования: `SPEC.md`.

## Архитектура

FastAPI и Postgres. Фоновые задачи лежат в таблице Postgres и выполняются воркером в процессе API. Внешние сервисы подключены через адаптеры и в тестах подменяются.

| Модуль (`backend/app/`) | Что делает |
|---|---|
| `auth/` | Вход через Mini App, Telegram Login, одноразовый код из бота, dev-вход |
| `appeals/` | Обращения: права (`policy.py`), маршрутизация, статусы, переписка, эскалация, поиск и склейка повторов, задача в Битрикс24 |
| `discussions/` | Общие обсуждения, голоса, комментарии, лента реализованного |
| `drafts/` | Черновик обращения из текста и голоса |
| `meetings/` | Запись совещания: расшифровка и черновики с цитатами |
| `analytics/` | Экран сводки, текст для бота, ежедневная рассылка |
| `notifications/` | Очередь уведомлений для бота, счётчик непрочитанного |
| `admin/` | Сотрудники, подразделения, категории, сроки, время сводки |
| `jobs/` | Очередь фоновых задач и расписания |
| `adapters/` | Claude, ElevenLabs, Telegram, Битрикс24 и их подмены для тестов |
| `seed/` | Демо-данные и команды загрузки |

## Запуск

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/). Postgres поднимается сам из пакета `pgserver`, Docker не обязателен.

```sh
cd backend
uv sync
uv run python scripts/dev.py
```

API откроется на `http://127.0.0.1:8000/api/v1/health`, интерактивная документация на `/api/v1/docs`.

С Docker:

```sh
cd backend
cp .env.example .env
docker compose up --build
```

Ключи внешних сервисов задаются в `.env`, полный список переменных есть в `.env.example`. Без ключей система работает: подача через форму, маршрутизация, статусы и сводка не зависят от внешних сервисов.

## Тесты

```sh
cd backend
uv run pytest                # все тесты
uv run pytest tests/e2e      # сквозные сценарии
```

`tests/e2e/test_scenarios.py` проходит через HTTP API шесть проверочных сценариев организаторов и демо-сценарий из десяти шагов.

Настоящие внешние сервисы проверяет отдельный скрипт. Он печатает только статус и время:

```sh
docker compose exec api python -m scripts.smoke_external
```

## Демонстрация и тестовые данные

Все данные синтетические. Команды загрузки:

```sh
uv run python scripts/dev.py python -m app.seed reset    # локально
docker compose exec api python -m app.seed reset         # в Docker
```

`reset` стирает данные приложения и загружает их заново. Его стоит выполнить перед показом. Даты считаются от момента загрузки, поэтому просроченные обращения есть в любой день.

| Что в сиде | Где посмотреть |
|---|---|
| 20 обращений A-001…A-020 из датасета организаторов | Список обращений |
| 8 подразделений, 18 категорий, сотрудники всех ролей | Настройки администратора |
| Просроченные обращения с эскалацией (A-001, A-007, A-011) | Фильтр «Просрочено», сводка |
| Реализованные улучшения (A-004, A-008) | Лента реализованного |
| Мотивированный отказ (A-017) | Карточка обращения |
| Открытое обсуждение с голосами (A-012) | Обсуждения |
| Повторы A-021 и A-022, склеенные с A-003 | Карточка A-003, счётчик участников |
| Разобранная запись совещания с тремя черновиками | Совещания, вход под руководителем закупок |

Вход под любой ролью без Telegram: dev-вход при `DEV_LOGIN_ENABLED=true`. На сервере для демо он выключен, вход идёт через Telegram-аккаунты, закреплённые файлом вне репозитория (`backend/README.md`, раздел «Демо-данные»).

## Что реализовано

- Подача формой, текстом, голосом и пересылкой, вложения, подтверждение черновика автором.
- Четыре роли и назначение ответственного, матрица доступа из `SPEC.md`.
- Маршрутизация по категории, заместитель при отсутствии, очередь администратора.
- Семь статусов, запрещённые переходы, обязательные причина отказа и результат, история событий.
- Срок первого ответа в рабочих днях и три шага эскалации.
- Поиск повторов через Claude, «Это другое», склейка с участниками.
- Вынос на обсуждение, голосование, показ имени автора только с согласия, лента реализованного.
- Режим «совещание»: расшифровка, черновики с цитатами, подтверждение каждого.
- Сводка с фильтрами, текст для бота, ежедневная рассылка во время из настроек.
- Создание задачи в Битрикс24 из обращения.
- Настройки администратора и уведомления через бота.

## Что подменено

В автоматических тестах подменены только внешние сервисы: Claude, ElevenLabs, Telegram и Битрикс24. Маршруты, база и фоновые задачи настоящие. В работающей системе используются настоящие адаптеры при заданных ключах.

Если Claude недоступен, форма работает как обычно, поиск повторов повторяет попытки в фоне, а сводка уходит по готовому шаблону с теми же числами.

## Известные ограничения

- Воркер выполняет задачи по одной: пока идёт долгая расшифровка записи, эскалация и сводка ждут своей очереди.
- При повторе обработки совещания после сбоя запись расшифровывается заново.
- Поиск повторов сравнивает новое обращение с последними 100 открытыми.
- Проверка времени сводки идёт раз в пять минут, рассылка приходит с такой же точностью. Если сервер простаивал больше часа после назначенного времени, сводка за этот день не уходит.
- Рабочие дни: понедельник–пятница по UTC+5, праздники Казахстана не учитываются.
- Обратной синхронизации с Битрикс24 нет.
- Качество распознавания и разбора на длинных реальных записях зависит от внешних сервисов и автоматическими тестами не проверяется.
- Вне объёма: анонимная подача, другие каналы кроме Telegram и форм, интеграция с 1С, нативные пуш-уведомления.
