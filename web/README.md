# Веб и экраны Mini App

React + TypeScript + Vite. Одни и те же экраны открываются в браузере и в Telegram Mini App на ширине телефона.

## Запуск на моке

Нужен Node.js 18+. Из корня репозитория:

```bash
npx -y @stoplight/prism-cli@5.15.11 mock -h 0.0.0.0 -p 4010 contract/openapi.yaml
```

В другом терминале:

```bash
cd web
cp .env.example .env
npm install
npm run dev
```

Откройте http://localhost:5173 и войдите через dev-вход.

## Настройки (`web/.env`)

| Переменная | Что задаёт |
|---|---|
| `VITE_API_BASE_URL` | Хост API без `/api/v1`: мок `http://localhost:4010`, локальный бэкенд `http://localhost:8000` или адрес сервера |
| `VITE_DEV_LOGIN` | `true` — показывать dev-вход. На сервере для демо `false`, бэкенд там же отвечает `403 dev_login_disabled` |
| `VITE_TELEGRAM_BOT_USERNAME` | Имя бота без `@` для виджета Telegram Login. Пусто — виджет скрыт. Виджет работает только на домене, привязанном к боту |
| `VITE_MOCK_ME_EXAMPLE` | Только для мока: пример `GET /me` (`owner`). Мок не помнит, под кем вход, и по умолчанию отдаёт сотрудника |
| `VITE_EMAIL_AUTH_MOCK` | `true` — вход и регистрация по почте работают на моке в памяти вкладки (`src/auth/email/mockEmailAuth.ts`), а не через API. Только для локальной проверки экранов; на сервере не задаётся |
| `VITE_ROLE_SWITCH_MOCK` | `true` — переключатель ролей работает на dev-пользователях локального бэкенда, а не через `POST /auth/switch`. Только для локальной проверки; на сервере не задаётся |

## Команды

- `npm run dev` — dev-сервер.
- `npm run build` — проверка типов и сборка в `dist/`.
- `npm test` — тесты.
- `npm run gen:api` — пересобрать `src/api/schema.d.ts` из `contract/openapi.yaml`. Запускать после каждого обновления контракта.

## Устройство

- `src/api/` — клиент API: `openapi-fetch` с типами из контракта. `unwrap()` возвращает данные или бросает `ApiError` с `code` и `message` из ответа.
- `src/auth/` — модуль входа. Экраны о способах входа не знают.
  - `methods/index.ts` — список способов: Telegram Login, dev-вход.
  - Способ входа — объект `AuthMethod`: `autoLogin` для входа без участия пользователя, `LoginButton` для экрана входа.
  - **Вход Mini App (T-06):** добавьте `methods/miniApp.ts` с `autoLogin` по `Telegram.WebApp.initData` → `POST /api/v1/auth/telegram/mini-app` и поставьте его первым в список. Экраны править не нужно.
- `src/app/navigation.ts` — разделы по `Me.permissions`. Стартовый экран у всех ролей один — «Сегодня» (`/`). Права клиент не вычисляет.
- `src/app/dictionaries.tsx` — русские подписи статусов, типов и ролей из `GET /api/v1/dictionaries`.
- `src/styles/global.css` — токены темы и весь визуальный язык. Светлая и тёмная тема: по системе или переключателем (на компьютере — внизу рейки, на телефоне — в меню под аватаром). Тёмная тема — нейтральные серые без синего оттенка; цвет остаётся у статусов, ссылок и красного действия. Mini App рисуется теми же токенами.

## Интерфейс

- **Оболочка** (`src/app/Shell.tsx`): на компьютере слева рейка разделов с кнопкой «Подать обращение», сверху шапка с заголовком экрана, поиском и уведомлениями. На телефоне рейку заменяет нижняя панель (до пяти пунктов, остальные под «Ещё»). Заголовок экран объявляет сам через `PageHead`.
- **«Сегодня»** (`src/pages/HomePage.tsx`): собирается из прав пользователя. Сводная фраза (`homeBrief.ts`), «Ждёт вас», две плитки с числами, шкала сроков (`dueTimeline.ts`), список и боковая карточка. Все данные — из существующих эндпоинтов.
- **Карточки поверх экрана**: обращение, обсуждение и совещание открываются панелью справа, форма подачи — окном по центру. Ссылка передаёт текущий экран в `state.background` (`src/app/background.ts`), `App.tsx` рисует карточку вторым набором маршрутов. По прямой ссылке (уведомление бота, адресная строка) тот же экран открывается отдельной страницей.
- **Вход и профиль** (`src/auth`, `src/profile`): почта и пароль — основной вход, Telegram ниже. Экран входа различает ответы сервера: неверные данные, заявка на рассмотрении или отклонена, доступ отключён, блокировка на 5 минут, временный пароль (тогда просит задать новый). Регистрация `/register` создаёт заявку; по ссылке `/invite/<токен>` можно зарегистрироваться по почте или войти через Telegram. В профиле `/profile` — почта, смена пароля, привязка и отвязка Telegram. Запросы собраны в `src/auth/email/emailAuth.ts`, правила форм и разбор ошибок — в `forms.ts`.
- **Переключатель роли** (`src/auth/switch`): демо-функция, видна только при непустом `Me.switch_targets`. В шапке рядом с уведомлениями — имя и роль, по нажатию список связанных пользователей; на телефоне он в меню профиля. В карточках переключателя нет: при открытой карточке-панели её сначала закрывают. Выбор вызывает `POST /auth/switch`, заменяет токен и перечитывает данные (вошедшая часть приложения привязана к id пользователя). Куда вести после смены роли, решает `destination.ts`: экран остаётся, если он есть у новой роли, открытая карточка обращения — если она ей видна, иначе «Сегодня».
- **Файлы обращения** (`src/appeals/AttachmentsSection.tsx`, `AttachmentViewer.tsx`): галерея плиток с превью, загрузка кнопкой или перетаскиванием на раздел, просмотр каруселью (стрелки, клавиши ← →, лента миниатюр). Ссылка на файл требует токен, поэтому превью скачивается через `fetch` и кешируется на сеанс (`useAttachmentUrl.ts`); картинка грузится, когда плитка показалась на экране. Удаления нет: в API нет такого маршрута.
- **Переписка в карточке** (`src/appeals/MessagesSection.tsx`): в карточке одна строка с последним сообщением, она работает как выключатель. Чат встаёт отдельной панелью слева от карточки на всю её высоту; если рядом места нет (уже 1100px), занимает место карточки, на телефоне — весь экран. По прямой ссылке чат стоит у правого края страницы. Автору, которому задали вопрос, чат открыт сразу. Esc скрывает чат, карточка остаётся (`src/app/escape.ts`).
- **Поиск** (`src/app/CommandBar.tsx`): Ctrl/⌘ + K или «/». Разделы, «Подать обращение» и обращения по `GET /appeals?q=`.
- **Уведомления** (`src/app/Notifications.tsx`): список из `GET /notifications`, отметка прочитанным через `POST /notifications/read`.
- **Фильтры «Входящих»** живут в адресе: `/queue?scope=assigned&due=overdue`.
- **Сообщения о результате** (`src/app/Toast.tsx`): `useToast()`.
- Значки — `lucide-react`. Числа на цветных плитках — `src/app/DotNumber.tsx`.

## Mini App (T-06)

Та же сборка открывается в Telegram как Mini App. Скрипт `telegram-web-app.js` подключён в `index.html`. Если в `Telegram.WebApp.initData` пусто, то это обычный браузер, и всё работает как раньше.

- Вход: `auth/methods/miniApp.ts` идёт первым в `authMethods` и отправляет `initData` в `POST /api/v1/auth/telegram/mini-app`. При отказе (`401`/`403`) показывается экран входа с `message`.
- Оболочка `telegram/MiniAppShell.tsx` (в `App` рядом с `AuthGate`, вне Telegram ничего не делает):
  - вызывает `ready()` и `expand()`;
  - красит рамку Telegram (шапка, фон, нижняя полоса) цветами нашей текущей темы (`telegram/theme.ts`); сами экраны под тему Telegram не перекрашиваются;
  - показывает кнопку «Назад» Telegram, когда в истории есть куда вернуться (`navigate(-1)`).
- Ссылки из бота (`telegram/startParam.ts`): `startapp` — это маршрут контракта (`Notification.path`), в котором `/` заменён на `_`. Например, `appeals_21` → `/appeals/21`, `discussions_5` → `/discussions/5`, `analytics` → `/digest`. Inline-кнопка `web_app` в боте может вести сразу на путь: `<MINI_APP_URL>/appeals/21`.
- Проверка в браузере без Telegram: откройте `http://localhost:5173/#tgWebAppData=<urlencoded initData>&tgWebAppVersion=8.0&tgWebAppPlatform=ios&tgWebAppThemeParams=<urlencoded JSON>`. Мок принимает любые `initData`.

## Сквозной прогон (W-09)

Основной сценарий «подал — взяли — уточнили — ответил — реализовано» под двумя пользователями (сотрудник закупок и руководитель закупок) в браузере, против настоящего бэкенда с dev-входом. Браузер — установленный Chrome, Playwright его не скачивает.

```bash
# 1. Бэкенд с dev-входом (Postgres поднимется сам)
cd backend && uv sync && DEV_LOGIN_ENABLED=true uv run python scripts/dev.py
```

```bash
# 2. Веб через прокси на бэкенд: в web/.env
#    VITE_API_BASE_URL=http://localhost:5173
#    VITE_API_PROXY=http://127.0.0.1:8000
#    VITE_DEV_LOGIN=true
cd web && npm run dev
```

```bash
# 3. Прогон
cd web && npm run e2e
```

Вход по почте проверяет `e2e/email-login.spec.ts`: ему нужна демо-учётка, `E2E_EMAIL=… E2E_PASSWORD=… npm run e2e`; без них эти тесты пропускаются. Каждый прогон создаёт новое обращение с пометкой `[e2e …]`. Сбросить демо-данные: `cd backend && uv run python scripts/dev.py python -m app.seed reset`. Другой адрес веба — `E2E_BASE_URL`, другой браузер — `E2E_CHANNEL` (например `msedge`).

Нет установленного Chrome — возьмите Chromium из Playwright:

```bash
cd web && npx playwright install chromium && E2E_CHANNEL=chromium npm run e2e
```

Прогон проверен и на текущей вёрстке, и на ветке дизайнера с формами действий в модальном окне (`web/design-next-4`, #141): кнопки ищутся в `.actions__buttons`, форма — `.actions__form` в обоих вариантах.
